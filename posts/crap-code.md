# vibe coding 一年，我终于明白：AI 没消灭屎山，只是让它长得更疯了

先说好，这篇不聊技术，就是纯吐槽。

最近接手了个用 Cursor vibe coding 的项目，原本以为 AI 加持下，代码总该优雅点吧？

结果一上午看下来，我沉默了。

## 那些让我沉默的瞬间

十几个分支的 if-else，一个文件里能出现三四处。复制粘贴的"祖传逻辑"，改一处漏三处。

SQL 直接字符串拼接，注入漏洞明晃晃挂在那，跟在门口贴了张"欢迎来攻击我"似的。

还有大段大段的死代码——连函数都没人调用，静静地躺在仓库里，像是给后来人上坟用的。

说好的代码版本管理呢？说好的代码 review 呢？说好的代码规范呢？

## 不是 AI 的锅，是人心散了

我越来越觉得，问题不在工具，在于"写完能跑就跑路"的人越来越多了。

以前没有 AI，至少还得自己一行行敲，敲的时候脑子是转的，哪里别扭自己知道。

现在 vibe 一下，功能跑通，截图发群，下班走人。至于这段代码半年后谁来维护、接手的人怎么骂——不在考虑范围内。

于是屎山没被铲平，反而因为生产速度变快，长得比以前更茂盛了。

## 但我也理解他们

说回来，我也不想站着说话不腰疼。

需求天天改，deadline 压死人，老板只要"能上线"。在这种环境下，谁还顾得上什么代码规范、什么可维护性？

AI 只是把"赶工"这件事变得更顺手了而已。

所以真正该问的也许是：我们是不是把"快"当成了唯一标准，却没人替"慢一点写好"买单？

## 最后想问一句

你接手过最离谱的 AI 写的代码是什么样的？

是 if-else 叠成金字塔，还是注释比代码还长，又或者是那种"我也不知道为什么能跑，但别动它"的神秘模块？

评论区聊聊，让我知道自己不是一个人在扛。
